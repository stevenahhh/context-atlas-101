03 DETERMINISTIC REDUCTION
결정적 규칙에 의한 요청 축소
아래 변환은 모델이 내용을 읽고 중요도를 판단하는 요약이 아니라, 메시지의 종류·위치·크기를 기준으로 수행하는 규칙 기반 처리이다. 설명의 범위는 이 하네스가 컨텍스트를 관리하고 관련 설정이 활성화된 기본 경로로 한정한다. SDK 소유 경로와 remote compaction 대상 모델의 예외는 뒤에서 별도로 다룬다. 각 수식의 토큰 값은 구현이 사용하는 추정량이며 문자열 길이와 UTF-8 바이트 수를 혼용해서는 안 된다.
5% ADMISSION
개별 도구 결과의 텍스트 예산 제한
Tool-admission은 도구 결과 하나가 요청 공간을 과도하게 차지하지 않도록 텍스트 예산을 제한한다. 전체 사용량과 무관하게 매 요청 실행된다. 다만 설정으로 비활성화할 수 있으므로 실행 여부는 설정에 달려 있다. 제한 대상은 도구 결과의 텍스트이며 이미지 부분을 이 예산에 맞춰 잘라내지는 않는다. [03]
cap = min(50,000, max(8192, floor(contextWindow × 0.05)))
기본 상한은 창의 5%를 기준으로 하되 8192토큰보다 작아지거나 50,000토큰보다 커지지 않도록 계산한다. 예를 들어 200k 창에서는 10,000토큰이 된다. 이 하한과 상한 때문에 작은 창과 큰 창에서는 실제 비율이 반드시 5%가 되지는 않는다.
출력이 예산을 넘으면 앞부분에 예산의 60%, 뒷부분에 20%를 배정해 발췌하고 생략 마커를 넣는다. 이는 원문 길이의 앞 60%와 뒤 20%를 보존하는 규칙이 아니다. 마커를 포함한 추정량이 여전히 초과되면 추가로 줄인다. 60%와 20%만으로 최종 요청량을 확정할 수는 없다.
50% REDUCTION GATE
오래된 대화와 도구 출력의 선택적 생략
일반 context-reduction은 사용량이 창의 절반 이상일 때 활성화된다. 이 단계에는 세 가지 변환이 포함되며 각각 보호하는 범위와 줄이는 대상이 다르다. 최근 정보를 보존한다는 목적은 공통이지만 보호 구간은 변환마다 따로 정의된다. [04]
연속 결과 접기 는 오래된 구간에서 같은 종류의 read/search/shell 작업 쌍이 이어지는 경우 결과 본문을 그룹 라벨로 바꾼다. 기본적으로 최소 2개가 모여야 하며 최근 메시지 5개는 이 단계의 대상에서 보호한다. 여러 메시지를 하나로 합쳐 의미 요약문을 작성하는 것이 아니라, 개별 결과의 상세 본문을 작업을 나타내는 짧은 표현으로 치환하는 처리이다.
옛 답변 자르기 는 최근 약 3000토큰의 보호 구간 밖에 있는 텍스트 전용 assistant 답변에 적용된다. 해당 답변이 800토큰을 넘으면 남길 본문의 목표를 800 × 0.3 = 240 토큰으로 계산하고 축소 마커를 덧붙인다. 기준은 원문 길이가 아니라 설정된 800토큰이므로, 원문이 2000토큰이라고 해서 600토큰을 남기는 것은 아니다. 도구 호출 등이 섞인 메시지까지 같은 방식으로 처리한다고 일반화해서도 안 된다.
옛 도구 결과 비우기 는 clearable 목록에 속한 도구 결과 중 최근 6개를 제외한 옛 텍스트를 마커로 바꾼다. 여기서 최근 6개는 clearable 도구 결과만 센 수이다. 앞선 변환에서 이미 발췌되거나 라벨로 바뀐 결과를 원문으로 되돌려 주지 않는다. 이 단계의 보호는 추가 삭제를 막는 범위에 그친다.

95 / 85 EMERGENCY LATCH
프롬프트 공간 초과에 대한 긴급 축소
Emergency-prune은 앞선 변환을 거친 뒤에도 메시지가 지나치게 큰 경우에 개입한다. 진입 조건은 메시지 추정량이 프롬프트용 창의 95%를 초과 하는 것이며 이미 켜진 상태는 85% 이하 가 되어야 해제된다. 두 판정의 분모는 모델의 전체 context window가 아니라 출력 공간을 제외한 프롬프트용 창이다. [05]
promptWindow = C − min(model.maxTokens, floor(C × 0.5))
engage: estimate > floor(promptWindow × 0.95)
release: estimate ≤ floor(promptWindow × 0.85)
유효한 양수 maxTokens 가 주어지면 모델 출력 한도와 창의 절반 중 작은 값을 출력 reserve로 확보한다. 유효 값이 없으면 이 reserve를 빼지 않는다. 같은 전체 창 크기라도 모델의 출력 설정에 따라 긴급 축소의 절대 토큰 경계는 달라진다. 이는 뒤에서 설명하는 compaction reserve와 별개의 계산이다.
긴급 축소에서는 4096바이트를 넘는 도구 결과 텍스트 블록을 앞 800자와 뒤 400자로 잘라낸다. 길이 판정의 단위는 바이트이고 보존할 발췌의 단위는 문자이다. 도구 출력 예산이 여전히 초과되면 일부 블록은 생략 마커만 남도록 줄인다. 전체 메시지 추정량이 그래도 충분히 작아지지 않으면 오래된 메시지까지 제거한다. 마지막 단계는 본문 축소를 넘어 메시지 자체가 요청에서 빠질 수 있는 처리이다.
이전 상태를 반영하는 히스테리시스 판정 HYSTERESIS / STATEFUL DEMO
히스테리시스는 진입과 해제에 서로 다른 경계를 사용하는 상태 유지 방식이다. 아래 비율은 앞선 변환 이후의 메시지 추정량을 프롬프트용 창으로 나눈 값이다. 비활성 상태에서 90%에 머무르면 축소가 켜지지 않지만 96%에서 활성화한 뒤 90%로 내려오면 활성 상태가 유지된다. 85% 이하까지 내려가야 해제된다. 입력을 움직이면 이 차이를 확인할 수 있으며 실험은 latch 판정만 재현하고 실제 도구 출력을 삭제하지는 않는다.

진입과 해제 경계를 분리하면 사용량이 한 임계값 주변을 오갈 때 요청 형태가 반복해서 전환되는 일을 줄일 수 있다. 이는 provider가 재사용할 수 있는 프롬프트 앞부분을 안정적으로 유지하려는 설계상의 이유와 연결된다. 다만 실제 캐시 적중률, 다시 과금되는 범위, 총비용의 변화는 provider와 요청 이력에 따라 달라지므로 측정 대상으로 남는다.
