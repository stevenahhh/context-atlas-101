# 컨텍스트 아틀라스 입문 (Context Atlas 101)

원문 《컨텍스트 아틀라스: 효율적인 에이전트 하네스의 구조》
(<https://stevenahhh.github.io/context-atlas-20261005/>) 를
**처음 보는 사람이 끝까지 막힘없이 읽을 수 있도록 순서를 다시 세워 쓴 학습 자료**입니다.

Live: <https://stevenahhh.github.io/context-atlas-101/>

## 다루는 범위

원문은 하네스의 효율을 **세 축**으로 나눕니다.

| 축 | 이 자료 |
|---|---|
| 보내는 토큰의 양 | **다룸** — 이 자료의 전부 |
| 과금 단가 (프롬프트 캐시 · 적중률 · TTL · prefix) | 다루지 않음 |
| 사용자의 대기 시간 (speculative · grace · 유휴 warm-up) | 다루지 않음 |

즉 **"하네스가 모델에 보내는 토큰을 어떻게 줄이는가"** 라는 한 축만 다룹니다.
프롬프트 캐시와 대기 시간 관리는 부하를 줄이는 운용 기법이지, 컨텍스트를 다루는 로직 자체는 아니기 때문입니다.

남는 것은 **2층 구조**입니다.

1. **1층 — 규칙으로 줄이기.** 요약을 부르지 않고 종류·위치·크기만 보고 자릅니다.
   (도구 출력 입장 제한 → 50% 축소 관문 → 95/85 긴급 축소)
2. **2층 — 요약으로 바꾸기.** 그래도 부족할 때 오래된 대화를 요약으로 대체합니다.
   언제 시작할지는 창 크기와 직전 절약률로 계산한 임계값이 정합니다.

여기에 요약 이후의 **단서 복원과 실패 관리**, **provider별 소유권 차이**, 다른 도구와의 비교가 붙습니다.

- 숫자·수식·조건은 원문 그대로 옮겼습니다. 새로 만든 수치는 없습니다.
- 원문이 "실측이 아니다", "단정할 수 없다"라고 밝힌 지점은 여기서도 그대로 밝힙니다.
- 순서는 `왜 → 무엇 → 어떻게` 로 다시 세웠습니다. (원문의 절 번호와 순서가 다릅니다.)

## 만들기

```bash
bun install
bun run build.ts     # content/*.md → index.html (단일 파일, 외부 의존 없음)
```

`index.html` 하나에 CSS·JS·데이터가 모두 인라인되어 있습니다. 별도 서버나 CDN 없이 열립니다.

## 구성

```
content/     장별 원고 (마크다운)
src/style.css
src/app.js   대화형 실험 (임계값 실험실, 히스테리시스, 세션 재생, 도구 비교)
src/figures.ts
src/data/    원문 페이지에서 추출한 실측 세션 데이터
build.ts     정적 사이트 생성기
BRIEF.md     집필 규칙 (범위·용어집·형식)
_source/     원문에서 추출한 장별 텍스트 (집필 참고용)
```

## 원문과 다른 점

- 범위를 한 축으로 좁혔습니다. (프롬프트 캐시 장과 비동기 컴팩션 장이 없습니다.)
- 히스테리시스는 "캐시 prefix를 안정시키려는 이유"가 아니라 "경계 근처에서 요청 형태가 반복 전환되는 것을 막는 이유"로 설명합니다.
- 모든 전문용어를 처음 등장할 때 한국어로 풀었습니다.
