# 11 · 옆 도구들은 어떻게 하나 — Codex · Claude Code와 나란히 보기

> **한 줄 요약:** 세 구현체는 같은 토대 위에 서 있지만, 이 하네스는 요약 전 결정적 축소와 실패 관리라는 두 갈래에서 다른 선택을 합니다.

## 이 장에서 배우는 것

- 이 하네스, Codex, Claude Code가 컨텍스트를 다루는 방식을 네 가지 축으로 비교하는 법
- 이 하네스만의 특징 두 가지와, 반대로 다른 도구가 더 가진 선택지
- 세 도구의 세션 재생 비교가 말해 주는 것과 말해 주지 않는 것

## 왜 이 이야기를 하는가

보내는 토큰을 줄이는 일은 이 하네스만 고민하는 문제가 아닙니다. 다른 코딩 에이전트도 같은 과제를 풉니다.

나란히 놓아 보면 두 가지가 보입니다. 어떤 선택이 모두가 하는 공통 설계인지, 그리고 어떤 선택이 이 하네스만의 특징인지입니다.

## 먼저, 비교의 근거가 다르다

비교 대상은 두 개입니다. 근거의 종류가 서로 다릅니다.

- **Codex:** 오픈소스입니다. 그래서 코드를 직접 대조했습니다. 기준은 clone HEAD `d4205609`의 `codex-rs` 소스입니다. 표의 Codex 칸은 코드로 확인한 값입니다.
- **Claude Code:** 소스가 비공개입니다. 그래서 공식 문서와, 이 장비에 남은 세션 로그의 usage 필드 관측만 근거로 씁니다.

::: warn 주의 · 비교의 비대칭
Claude Code 칸은 문서가 보장하는 범위의 서술입니다. 코드 수준에서 단정한 내용이 아닙니다. "문서에 없음"은 "구현에 없음"이 아닙니다. Claude Code 칸에서 "없음"이라고 적힌 곳은 모두 관측 범위 안에서만 그렇다는 뜻으로 읽어야 합니다.
:::

## 세 구현체의 공통 토대

차이를 보기 전에 같은 점부터 짚겠습니다. 세 구현체는 모두 다음 위에 서 있습니다.

- 요약에는 지금 대화 중인 모델을 그대로 씁니다.
- 요약 입력에는 공통 요약 지시를 마지막 사용자 메시지로 붙입니다.
- 최근 대화 구간은 일부 그대로 보존합니다.
- 도구 출력은 어떤 방식으로든 잘라서 다룹니다. 자르는 시점과 장소만 다릅니다.

차이는 이 토대 위에서 갈라지는 길에서 생깁니다.

Codex에는 세 갈래가 있습니다.

1. 원격 compaction을 지원하는 모델이면, 서버에 `CompactionTrigger` 아이템을 보냅니다. 그리고 서버가 만든 `Compaction` 출력을 받습니다.
2. `Feature::TokenBudget`이면, 요약 없이 새 컨텍스트 창을 설치합니다.
3. 둘 다 아니면 로컬에서 요약합니다.

Claude Code는 로컬 요약 경로 하나에, 서버 측 context editing이 함께 있습니다. 이 하네스는 요약 이전에 결정적 축소 층을 하나 더 둡니다.

## 네 축 비교표

| 비교축 | 이 하네스 | Codex | Claude Code |
|---|---|---|---|
| 축소 트리거 | 적응 임계값 + 미완성 job 유예 + 하드 리밋의 다층 판정 | 한도 = 창의 90%, 하드캡 95% 외 | 창 한계 도달 시 자동(~1M 모델에서 ~967K) |
| 요약 생성 | 검증을 거친 뒤 적용 | 로컬·원격·토큰예산 3분기. 로컬은 동기 | 동기 요약 요청 후 즉시 설치 |
| 요약 이후 문맥 | 요약 + 보존 메시지 + restoration 라벨 | 로컬: 최근 user 최대 20k토큰 + 요약. 원격 v2: 최근 64k토큰 + Compaction 출력 | 요약 + 여러 자료 재주입 + 최근 수정 파일 5개 재읽기 |
| 도구 출력 처리 | 요청마다 결정적으로 줄임. 원본 유지 | 기록 시점에 `truncation_policy`로 중간 생략(exec 기본 10k토큰) | 서버 측 context editing(베타), 100K에서 치환 |

표 칸은 짧게 줄였습니다. 아래에서 축마다 풀어 설명하겠습니다.

## 축마다 풀어 보기

### 축소 트리거 · 언제 줄이기 시작하는가

**이 하네스**는 여러 층으로 판단합니다. 적응 임계값은 창 크기와 직전 절약률을 보고 움직입니다. 아직 끝나지 않은 job이 있으면 잠시 기다려 주는 유예도 있습니다. 마지막으로 넘으면 안 되는 하드 리밋이 있습니다.

**Codex**는 한도를 창의 90%로, 하드캡을 95%로 둡니다. 그 밖에 다음 계기로도 요약이 일어납니다.

- `ContextWindowExceeded` 에러가 나면 요약 후 재시도
- 턴이 끝난 뒤의 임계값(기본은 꺼져 있음)
- 수동 `/compact`
- 모델 전환

**Claude Code**는 창 한계에 닿으면 자동으로 요약합니다. 문서 기준으로 ~1M 모델에서는 ~967K 지점입니다. `/autocompact`나 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`로 조정할 수 있고, 수동 `/compact`도 있습니다.

### 요약 생성 · 어떻게 만드는가

**이 하네스**는 요약을 만든 뒤 바로 쓰지 않고 먼저 검증합니다. 통과한 결과만 활성 문맥에 적용합니다.

**Codex**는 로컬, 원격, 토큰예산의 세 갈래입니다. 로컬 요약은 동기 스트리밍입니다. 즉 요약이 끝날 때까지 기다린 뒤 바로 새 이력을 설치합니다.

**Claude Code**는 동기로 요약을 요청합니다. 공통 프롬프트 끝에 요약 지시를 마지막 user 메시지로 붙입니다. 결과가 오면 즉시 설치합니다.

::: term 용어 · 동기(synchronous)
일이 끝날 때까지 다음 단계가 기다리는 방식입니다. 요약이 동기라면, 그 요약이 끝나야 대화가 이어집니다.
:::

### 요약 이후 문맥 · 요약하고 나면 무엇이 남는가

**이 하네스**는 요약, 보존 메시지, restoration 라벨을 남깁니다. 라벨은 파일 경로, 작업, 스킬 이름입니다. 이름표만 다시 붙일 뿐 본문을 다시 읽어 오지는 않습니다.

**Codex**는 경로마다 다릅니다.

- 로컬: 최근 user 메시지를 최대 20k토큰까지 남기고 요약을 붙입니다.
- 원격 v2: 최근 64k토큰을 보존하고 `Compaction` 출력을 붙입니다.

**Claude Code**는 문서상 복원 단계가 풍부합니다. 요약에 더해 다음을 다시 넣습니다.

- CLAUDE.md, 메모리, 계획, git 스냅샷
- 최근 수정한 파일 5개를 다시 읽어 온 내용
- 스킬 본문(5K/25K 상한)

### 도구 출력 처리 · 큰 출력을 어떻게 다루는가

**이 하네스**는 provider 요청을 보낼 때마다 규칙으로 줄입니다. 5% 예산, 접기, 마커를 씁니다. 세션 원본은 그대로 둡니다.

**Codex**는 기록하는 순간에 한 번 자릅니다. 모델별 `truncation_policy`로 가운데를 생략합니다. exec 출력의 기본값은 10k토큰입니다. 이 생략은 실행 중인 화면용이고, rollout 원본은 보존됩니다. 아예 지우는 일은 컴팩션 때 합니다.

**Claude Code**는 서버 측 context editing(베타)을 씁니다. 100K에 이르면 오래된 tool uses를 placeholder로 바꿉니다. 클라이언트 쪽 이력은 그대로 남습니다.

## 이 하네스만의 두 갈래

두 구현체와 비교하면 이 하네스의 특징이 두 가지로 드러납니다.

### 첫째 · 요약 이전의 결정적 축소 층

- Codex는 도구 출력을 기록 시점에 한 번 자릅니다(exec 기본 10k토큰). 지우는 일은 요약이 맡습니다.
- Claude Code는 오래된 tool uses 치환을 서버에 맡깁니다(100K에서).
- 이 하네스는 provider 요청마다 규칙으로 도구 출력과 답변을 다시 줄입니다.

차이는 **언제, 몇 번** 줄이느냐에 있습니다. Codex의 자르기는 기록할 때 한 번뿐입니다. Claude Code는 100K라는 경계에 닿아야 서버가 움직입니다. 이 하네스는 원본을 그대로 두고, 요청을 보낼 때마다 규칙을 새로 적용합니다. 그래서 원본을 잃지 않으면서도 매번 보내는 양을 줄일 수 있습니다.

그래서 무엇이 좋아질까요? 같은 대화라도 요약에 도달하는 시점이 늦어집니다. 요약은 LLM을 불러야 하는 무거운 일이니, 덜 자주 하게 되는 셈입니다.

::: analogy 비유 · 책상 정리
Codex는 서류를 책상에 올리는 순간 한 번 잘라 둡니다. Claude Code는 관리인이 와서 오래된 서류를 빈 표지로 바꿔 줍니다. 이 하네스는 일을 시작할 때마다 책상 위를 규칙대로 다시 정돈합니다. 그래서 "책상을 통째로 치우고 메모만 남기는" 요약까지 가는 날이 늦게 옵니다.
:::

### 둘째 · 실패 관리

토큰을 줄이는 장치는 실패할 수도 있습니다. 요약이 거듭 실패하면 같은 실패를 반복하지 않도록 끊어 주는 circuit breaker가 이 하네스에는 있습니다. 텍스트 없는 응답을 감시하는 no-text monitor도 있습니다. 둘 다 잘못된 결과가 활성 문맥에 들어가는 것을 막는 장치입니다. 두 구현체에서는 이에 해당하는 장치가 확인되지 않았습니다.

::: warn 주의
"확인되지 않았다"는 표현을 그대로 받아들여야 합니다. 특히 Claude Code는 소스를 볼 수 없으므로 "없다"고 단정할 수 없습니다.
:::

## 반대 방향의 차이

이 하네스가 모든 면에서 더 많이 가진 것은 아닙니다.

- **Codex**는 원격 compaction 지원 모델에서 요약 자체를 서버에 맡깁니다. `Feature::TokenBudget`으로 요약을 아예 생략하는 갈래도 있습니다. 구조적 선택지가 더 큽니다.
- **Claude Code**는 요약 뒤에 CLAUDE.md, 메모리, 최근 수정 파일 5개, 스킬 본문을 디스크에서 다시 읽어 붙이는 복원 단계가 문서에 적혀 있습니다. 서버 측 context editing은 클라이언트 구현 없이 같은 효과를 냅니다.

이 하네스의 restoration tracker는 라벨만 다시 넣습니다. 세부 본문은 복원하지 않습니다. 이 점이 Claude Code와 대조되는 지점입니다.

## 세 도구의 창 움직임 재생

원문은 앞 장과 같은 재생 방식을 세 도구에 적용했습니다. 도구마다 가장 긴 세션 하나씩을 골라 나란히 놓았습니다.

- 가로축은 각자의 활동 시간입니다. 10분 넘게 비어 있던 구간은 뺐습니다.
- 재생은 진행률을 맞춰 동시에 흐릅니다. 같은 진행 지점에서 창이 얼마나 찼는지 비교할 수 있습니다.
- 두 상용 도구의 로그에는 컴팩션 장면이 없습니다. 그래서 초점은 창이 차오르는 기울기와 도달 지점입니다.

| 도구 | 모델 | 세션 시점 | 메시지 | 모델 호출 | 구간 | 활동 | 최대 프롬프트 | 창 | 컴팩션 | 컴팩션 후 잔존 | 기울기(토큰/활동h) |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 이 하네스 | 여러 모델(devin 등) | 2026-09-27 22:20 ~ 2026-09-30 00:29 | 4,883 | 2,309 | 50.1h | 13.8h | 307,310 | 미기록 | 11 | 31.7% | 19,816 |
| Claude Code | claude-opus-5 | 08-24 21:10 ~ 08-24 22:49 | 1,685 | 810 | 4.2h | 1.6h | 483,851 | 미기록 | 0 | 없음 | 278,414 |
| Codex | gpt-6-astra | 09-07 14:08 ~ 09-07 14:37 | 218 | 101 | 9.9h | 0.5h | 339,050 | 828,400 | 0 | 없음 | 583,244 |

칸 몇 개를 풀어 두겠습니다.

- **구간**은 세션 처음부터 끝까지의 시간입니다. **활동**은 그중 빈 구간을 뺀 시간입니다.
- **최대 프롬프트**는 한 번의 모델 호출에 들어간 입력 토큰을 사용량 필드에서 모두 더한 값의 최댓값입니다.
- **창**은 모델의 컨텍스트 창 크기입니다. 이 하네스와 Claude Code 로그에는 남지 않았습니다. Codex만 828,400을 실측으로 남겼습니다(최대 사용 약 41%).
- **기울기**는 활동 1시간당 창이 얼마나 차올랐는지입니다.

컴팩션 기록은 이 하네스 세션에만 있습니다(11회). 나머지 두 세션은 창 한계에 닿지 않아 컴팩션 장면이 없습니다.

::: warn 주의 · 일반 성능 비교가 아닙니다
도구당 세션 하나(n=1)의 비교입니다. 세 세션의 작업 내용도 서로 다릅니다. 그러니 "어느 도구가 더 효율적이다"라는 일반적인 주장으로 읽으면 안 됩니다. 값은 각 도구가 로컬에 남긴 사용량 필드에서 뽑은 실측입니다.
:::

## 한 줄 정리

세 구현체는 같은 모델로 요약하고 최근 대화를 일부 보존하는 공통 토대를 갖습니다. 이 하네스는 그 위에 요청마다 다시 줄이는 결정적 축소와 실패 관리 장치를 더했습니다. 반대로 Codex는 서버 위임과 요약 생략 갈래를, Claude Code는 풍부한 복원 단계를 가집니다. Claude Code 칸과 세션 재생 표는 모두 한정된 근거라는 점을 함께 기억해야 합니다.
